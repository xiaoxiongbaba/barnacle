# Barnacle 需求文档

> 每完成一个功能就在这里勾选一次（`- [ ]` → `- [x]`），并在末尾的「变更记录」里补一行。
> 最后更新：2026-10-23

## 1. 产品定位

Barnacle 是一个**自托管的像素办公室**，里面住着一支 AI 团队。

- 它是类似 OpenClaw 的**聚合型智能体平台**，不依赖 Claude Code：用户自己接入模型（Anthropic、OpenAI 兼容接口、DeepSeek、MiniMax、Ollama……），用 **SOUL（灵魂）+ 技能** 给每个小人设定性格与角色。
- 小人们不是各干各的，而是**像团队一样协作**：互相求助、委派、在项目里接力完成工作。
- 办公室是可视化界面：谁在干活、干到哪一步、卡在哪里需要人，一眼就能看到。没有活的时候，小人们会喝咖啡、打乒乓、聊天（空闲动画照搬 Habblaud）。

## 2. 设计原则

1. **零配置**：下载即用，不需要写 YAML、配 Docker 网络才能开始。（OpenClaw / Hermes 用户最大的痛点）
2. **看得见**：每个小人在做什么、记住了什么、和谁协作，都能在办公室和抽屉里看到。
3. **管得住**：权限由系统强制执行，不靠提示词；人写的东西小人不能改；重要的事等人确认。
4. **克制**：只做对小团队有用的功能，不堆工具，不做 AI 社交动态流（Clawith 已经验证这是噪音）。
5. **省 token**：任务按需开新上下文，不把整段历史反复重发。

## 3. 约束

- 第一阶段小人只有「技能 + 联网查资料」两类能力：**不执行 shell 命令、不写文件**。
- LimeZu 素材只能放在被 git 忽略的 `packs/local/`，不得提交、发布或随部署分发。
- Habblaud（MIT）的代码和美术需保留署名；不使用 Habblaud 的品牌（名字、logo、吉祥物）。
- 所有模型调用都在服务端；API 密钥加密存储，永不发到浏览器。
- 界面三语：English / 日本語 / 繁體中文。

## 4. 功能清单

### 4.1 基础平台

- [x] Fastify 服务端 + Phaser 网页端，npm workspaces，Docker 部署
- [x] SQLite 存储（成员、事件、设置、模型、任务……）
- [x] 状态上报协议（`POST /api/occupants/:id/status`）与 WebSocket 实时推送
- [x] 办公室令牌（token）鉴权，设置页可轮换
- [x] 三语界面（en / ja / zh-Hant）
- [x] 美术包机制（内置美术 + 本地 LimeZu 包，后者不分发）
- [x] 移除对 Claude Code 自动会话的依赖（原 watcher、usage 统计已删除）

### 4.2 办公室与地图编辑器

- [x] 房间默认留白，地板、墙、家具都是用户自己摆放的「零件」
- [x] 地图编辑器：地板 / 墙 / 家具 / 移动 / 擦除 / 房间区域工具
- [x] 笔刷与矩形两种模式、撤销 / 重做、保存
- [x] 家具目录（参考 Habblaud 的种类，含座位朝向）
- [x] Habblaud 风格的程序化像素美术（地板、墙体自动拼接、家具、角色）
- [x] 室外场景：草地、树、路灯、人行道，马路放在屏幕下方，有车辆通行
- [x] 办公室放大铺满屏幕，镜头适配、缩放、聚焦到某人
- [x] 状态路由：不同状态走到不同房间（空闲去休息室、工作回工位……）
- [x] 默认办公室布置好：研究室、写作室、设计室、营运室（各 6 个工位）、会议室、休息室、接待处、机房
- [x] 小人按职位自动归属对应办公室（也可在设置里手动指定），工作时回到自己固定的工位

### 4.3 界面（照搬 Habblaud 风格）

- [x] 顶栏：品牌、计数器（房间 / 成员 / 工作中 / 需要你）、语言、镜头按钮
- [x] 左侧栏：搜索、按房间分组的成员列表（头像、角色标签、状态点）
- [x] 动态流与滚动字幕
- [x] 右侧抽屉：头像、角色、模型、所在房间、状态、当前动作、时间线
- [x] 窄屏适配（抽屉变底部面板）
- [x] Pixelify Sans 字体

### 4.4 模型接入与聊天

- [x] 模型提供方：Anthropic 与 OpenAI 兼容接口（OpenRouter、DeepSeek、Gemini、Ollama、MiniMax……）
- [x] API 密钥 AES-256-GCM 加密存储
- [x] 每个小人单独指定模型、回复长度
- [x] 与小人聊天（流式输出），聊天内容不进入公开状态

### 4.5 灵魂与技能

- [x] 每个小人的职位、SOUL（性格、语气、边界）、AGENTS（工作方式）
- [x] 灵魂模板：研究员、写手、行销、专案助理
- [x] 共享技能库：新建、编辑、删除
- [x] 导入 / 导出 SKILL.md（name + description 前置，正文按需加载）
- [x] 内置 4 个技能：调研简报、周报、文案润色、社交贴文
- [x] 给小人勾选可用技能

### 4.6 任务执行

- [x] 在抽屉里给小人派任务，结果以 Markdown 渲染，可复制
- [x] 工具循环：`read_skill`、`web_search`（DuckDuckGo）、`web_fetch`
- [x] `web_fetch` 防 SSRF：只允许 http(s)、拒绝内网 / 本机地址、重定向逐跳检查、大小上限
- [x] 每一步工具调用都映射成办公室状态和一行动态（思考 → 写作，查资料 → 研究）
- [x] 每人一次只做一个任务，其余排队；可取消
- [x] 服务器重启后：中断的任务标为失败，排队的任务继续
- [x] 步数上限（16）与超时（10 分钟），最后一轮要求收尾
- [x] 去掉模型的 `<think>` 思考过程（MiniMax、DeepSeek R1、Qwen 等）
- [x] 任务提示词带上当前日期、星期、时区

### 4.7 空闲动画（照搬 Habblaud）

- [x] 每人根据 id 生成固定性格（2–3 个特点 + 社交度 + 游戏水平）
- [x] 单人活动：咖啡、饮水机、零食、沙发 / 打盹、玩手机、看书、发呆、街机、照镜子、伸懒腰
- [x] 组局活动：乒乓球（五分制 + 观众）、猜拳（赌金币）、聊天（工作 / 闲聊 / 笑话 / 八卦）、看电视、打电动
- [x] 三语台词、头顶图标、金币飘字
- [x] 接到任务时说「我被叫走啦！🏃」并中断整局
- [x] 地图编辑时暂停空闲活动

### 4.8 分层记忆（借鉴 Hermes）

- [x] 长期记忆：小人自己的笔记（2,200 字）+ 全办公室共享的「关于你」（1,375 字），每次任务冻结快照写进提示词
- [x] `memory` 工具：添加 / 替换 / 删除，满了要求先合并或删除
- [x] 人写的或改过的条目锁定，小人只能遵守不能改（针对 Hermes「覆盖手动修改」的问题）
- [x] 翻记忆：任务和聊天进 SQLite FTS5（trigram，支持中日文）全文索引
- [x] `recall` 工具：搜索过去的工作，并能按编号打开整个旧任务
- [x] 离步数上限两轮时提醒先存记忆
- [x] 抽屉「记忆」区块：用量条、增删改、边打字边搜索过去的工作（不打断输入法）

### 4.9 定时任务

- [x] 规则：每天、工作日、每周几天、每隔几小时、只一次
- [x] 按用户浏览器时区计算（服务器用 UTC 也准时），正确处理夏令时
- [x] 到点自动派任务，小人起身去工位；任务带 ⏰ 标记
- [x] 上一次还没跑完就跳过；办公室关闭期间错过的只补跑一次
- [x] 立即执行（不影响原定时间）、暂停 / 恢复、编辑、删除
- [x] 已完成的任务一键「设成定时」

### 4.10 多 Agent 协作 ①：委派与求助（借鉴 Clawith A2A）

- [x] 同事名单写进系统提示词（名字、职位、技能、现在忙不忙；只列有模型的小人）
- [x] `ask_colleague` 工具：向同事问一个快问题，拿到回答后继续（对方最多 6 步）
- [x] `delegate` 工具：把一件事交给同事，对方完成后带着结果自动继续（不轮询、不重复发）
- [x] 发起方等待期间头顶显示 ⏳，任务步骤里能看到交给了谁、拿回了什么；等待时间不计入任务超时，状态有心跳不会被判成空闲
- [x] 子任务记录父任务，抽屉里能从子任务跳回父任务、从父任务的步骤点进子任务
- [x] 防循环：委派链上已出现的人不能再被委派；委派最多 3 层、每个任务最多 4 次请求；每次最多等 8 分钟
- [x] 取消发起方的任务时，连带取消它在等的子任务；重启后无人等待的子任务自动取消
- [x] 动画：发起方带着文件走到同事工位递交、对方应答，回座位等待；完成后同事把结果送回
- [x] 动态流里显示「请 B 帮忙：……」「B 交回了结果」「帮 A 做事：……」

### 4.11 多 Agent 协作 ②：项目讨论串（借鉴 Clawith 群聊 + 规划器）

- [x] 「项目」：一个目标 + 参与成员 + 讨论串；侧栏「项目」列表，抽屉里看项目
- [x] 用 @ 指派：只 @ 一个人就直接开工；@ 多人时先走一次规划器（点名字即可插入 @）
- [x] 规划器：单次模型调用，不用工具；输出目标、完整计划、第一批开工的人；格式不对重试一次，失败则从第一个被 @ 的人开始
- [x] 规划规则：严格按 @ 绑定分工、不凭空加审核 / 汇总步骤、打招呼直接各回一句；区分「建议」与「严格」模式
- [x] 公开接力：每人用自己的身份在讨论串发言，带着具体结果 @ 下一个人；@you 表示需要你回复
- [x] 防止来回推：你每发一条消息后，最多 12 个回合、每人最多 4 个回合
- [x] 项目看板：你写的项目说明 + 每人针对本项目的笔记（`project_note`，所有成员都能读）
- [x] 动画：项目进行中成员坐进会议室，交棒时把文件递给下一个人；结束后各回各位
- [x] 每个回合都是成员任务列表里的一项（📋），能跳回项目；可停止、结案、重新开启、删除
- [x] 项目结束时自动汇总交付物：一轮结束（至少两人发言）或结案时，写「📦 交付物汇总」贴进讨论串、显示在项目顶部，并存进每位成员可搜索的过往工作
- [x] 定时任务可以发起一个项目（例如每周一：研究员查资料 → 写手写周报）：每次开一个「名称 · 日期」的新项目；项目里可一键「定时重复这个项目」；上一次还在进行就跳过

### 4.12 审批与验收

- [x] 交付物「采纳 / 退回重做」：退回理由写进该小人的记忆，并带着上一版和理由自动重做（标 ↩）
- [x] 敏感操作先停下来进入「需要你」状态，等人批准（权限由系统强制，不靠提示词）：设置 →「权限」里每个动作可选允许 / 先问我 / 禁止；默认改「关于你」要先问；等待最多 30 分钟，不计入任务超时
- [x] 顶栏「需要你」计数器点开就是待处理列表：待批准、等你回复的项目、经验草稿、技能提议
- [x] 经验库：小人只能提交经验草稿（场景 / 问题 / 解决 + 适用条件与失效信号），人确认后才入库；任务中按需检索（设置 →「经验库」可浏览、手动新增、编辑）
- [x] 技能自沉淀改为「提议」：小人提议新技能或修改，人确认后保存（新技能可直接交给提议者）
- [x] 人手动改过的技能标记锁定，不被自动覆盖：小人不能直接写技能；改你动过的技能时提议里会提醒

### 4.13 成果验收页

- [x] 顶栏 📦「成果」按钮，角标显示待验收数量；任务做完右下角弹出「XX 完成了…… → 验收」
- [x] 成果页：待验收 / 已采纳 / 已退回 / 失败 / 全部 / 项目，可按成员筛选、搜索
- [x] 全文阅读：当初的要求、完整结果（表格正常显示）、工作过程
- [x] 核对来源：列出它（以及它委派的同事）实际读过的网页，可点开核对；没读任何网页时提醒你特别留意
- [x] 在成果页直接采纳 / 退回重做（采纳后自动跳到下一份待验收）、复制、下载 .md、看重做的版本
- [x] 有交付物汇总的项目也列在成果里

### 4.14 工位

- [x] 工位 = 办公椅 + 前面的桌子和电脑；绑定记在椅子上（员工 → 椅子坐标），随地图保存；员工所在房间就是工位所在房间
- [x] 没有工位的人自动按职位分到对应办公室的空位并保存（新成员加入、启动时都会检查）
- [x] 桌上显示名牌（主人不在座位时显示）；工作时回到自己的工位，别人的工位不会被占
- [x] 在办公室点空工位：选人分配；点有人的椅子：工作台 / 详情 / 换工位；点电脑：直接打开主人的工作台
- [x] 换工位：在办公室里高亮可选工位（空位绿、别人的橙、自己的蓝），点一下换过去；占别人的位置会互换；抽屉和设置里也能换
- [x] 工作台：工位、模型、职位、灵魂、技能（技能跟着人走，换工位不变）
- [x] 地图编辑器：移动椅子时绑定跟着走；删掉有人的椅子，保存前提醒，之后自动分到其他空位
- [ ] 房间默认技能：分到某个办公室的新员工自动带上该房间的技能

### 4.15 组织架构：部门经理、CEO、董事长〔①②③ 已完成（授权建议归入 ④），④ 待做〕

**思路**：把办公室变成一家公司。每个工作室是一个**部门**，部门里有一位**部门经理**，每天汇总本部门的工作向上汇报；**CEO** 汇总各部门，并在你授权的范围内替你审批；**你是董事长**，打开自己办公室的电脑，就能看到全公司的汇总和真正需要你拍板的事。部门经理和 CEO 都是可选的，不开就保持现在的样子：所有汇报和审批直接到你这里。

**汇报链**

```
成员（做事）→ 部门经理（部门日报）→ CEO（公司日报 + 代批）→ 董事长（你）
                       没开 CEO 时直接到你 ↗        没开经理时你看到的是自动统计
```

**设计原则**

- 汇报要**有据可查**：日报根据当天真实的记录写（完成的任务、交付物、失败、卡住等你的事、项目进展），每一条都能点回原始任务；模型只负责组织语言，不能编造进度。
- 代批要**可追溯、可推翻**：CEO 每一次代你批准或拒绝都有记录和理由，你随时可以看、可以推翻；拿不准就上交给你。
- **授权一点点放**：CEO 一开始什么都不能批，由你按类别授权；系统根据你过去的审批习惯建议授权，但必须你点头。
- 都能关：组织功能整体、每个部门的经理、CEO 各自有开关。
- 控制成本：日报每天每层一次模型调用，时间和频率可调，显示大概的 token 花费。

**① 部门与部门经理**

- [x] 设置里新增「组织」页：总开关；每个工作室（部门）可指定一位部门经理（从该部门成员中选），或不设
- [x] 部门经理在办公室里有标识（名牌上加「经理」），抽屉里显示所管部门
- [x] 部门日报：默认每个工作日 18:00（可改时间、可改为每周）；内容固定分区——今日完成（附交付物链接）、进行中、问题与风险、需要上级决定的事
- [x] 日报只依据当天的真实记录生成，附「依据」列表（对应的任务 / 项目 / 审批），没有记录就写「今天没有进展」
- [x] 日报交给 CEO；没开 CEO 时直接进董事长工作台
- [x] 动画：到点时经理拿着报告走到 CEO 办公室（或你的办公室）交给对方
- [x] 向部门派活：可以把任务交给「部门」，由部门经理分给合适的成员（沿用 4.10 委派），并在日报里跟进
- [x] 没设经理的部门：董事长工作台显示自动统计（完成数、进行中、失败、待验收），不调用模型

**② CEO**

- [x] 「CEO 办公室」：默认布局新增这个房间；已有办公室可在地图编辑器里加，再在「组织」页指定
- [x] 公司日报：汇总各部门日报——重点进展、跨部门问题、CEO 今天代批了什么、需要董事长决定的事
- [x] 授权代批：你按类别授权 CEO 处理收件匣里的事（例如某些权限动作的审批、经验草稿、技能提议、例行成果的验收），没授权的仍然上交给你
- [x] CEO 做决定时参考：申请内容、申请人、权限设置、经验库、你过去对同类事情的决定（作为先例）；输出「批准 / 拒绝 / 上交董事长」和理由，并引用依据的先例
- [x] 永远不能代批：被设为「禁止」的动作、CEO 自己发起的请求、你标记为高风险的类别（如以后的远程执行命令、花钱的操作）
- [x] 代批记录：每一笔都可在董事长工作台查看，一键推翻（推翻后按你的决定执行，并作为新的先例）

**③ 董事长办公室与董事长工作台**

- [x] 「董事长办公室」：默认布局新增；你（人类成员）的工位在这里
- [x] 点你桌上的电脑，打开**董事长工作台**：

#### 备选：远程节点（让小人用其他电脑上的 Claude Code / Codex）

背景：Barnacle 多半部署在 NAS 或服务器上，要做写代码之类的事需要用到别的电脑。做法是在目标电脑上装一个小的「Barnacle 节点」程序，由它**主动连回 NAS**（不用开端口，NAT、Windows、Mac 都能用；人在外面可以走 Tailscale）。Barnacle 的模型不直接操作那台电脑，只把任务交给那台电脑上已登录的 Claude Code / Codex，所以不碰那边的密钥。

- [ ] ① 节点程序与配对：一行命令启动（如 `npx barnacle-node`），输入页面上的配对码连上；每个节点单独的令牌，可在设置里吊销；显示在线 / 离线
- [ ] ① Claude Code 任务：在白名单项目目录里以无交互模式运行（`claude -p`），过程与结果传回
- [ ] ① Codex 任务：以无交互模式运行（`codex exec`），开启其沙箱，只允许写工作目录
- [ ] ① 远程电脑可绑定到某张桌子的「电脑」：坐在该工位的小人多一个「在这台电脑上用 Claude Code / Codex 做…」的工具；点电脑可看连线状态
- [ ] ① 权限：新增「远程写代码」「远程执行命令」，默认「先问我」；结果附上改动的文件与 diff 摘要，进成果页验收
- [ ] ① 节点本机有暂停开关，所有远程操作留记录
- [ ] ② 白名单 Shell：默认关闭，打开后只能在白名单目录执行
- [ ] ③ 远程图形界面操作（截图 + 鼠标键盘）：复杂且不稳定，需要时再做

不选的方式：SSH（要开入站端口、管密钥，Windows 和外出笔记本不好连，权限难细分）；MCP 直连（同样要 NAS 能连到对方，每种能力要单独找服务）。
